Rukomeza REST API

JSON over HTTPS, versioned under /api/v1/. The complete OpenAPI 3.1 contract is available for download.

Download openapi.yaml Authentication Endpoints

Authentication

Obtain an opaque bearer token from POST /api/v1/auth/login or POST /api/v1/auth/register, then send it on every protected request:

Authorization: Bearer <token>

Tokens are stored as SHA-256 hashes, can be revoked with POST /api/v1/auth/logout, and are never placed in cookies. Public catalogue endpoints need no token.

Money is serialised as decimal strings (for example "15000.00") to avoid floating-point rounding. Prices are always recalculated on the server.

Quick start

# 1. Log in and keep the token
curl -s -X POST https://YOUR-APP.onrender.com/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"amina@example.com","password":"Customer#2026"}'

# 2. Add a product to the cart
curl -s -X POST https://YOUR-APP.onrender.com/api/v1/cart/items \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"product_id": 1, "quantity": 2}'

# 3. Check out (atomic stock decrement)
curl -s -X POST https://YOUR-APP.onrender.com/api/v1/orders \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"full_name":"Amina K.","phone":"+256700000000","address":"12 Market Road","city":"Kampala","gateway":"MOCK"}'

# 4. Simulate a successful payment
curl -s -X POST https://YOUR-APP.onrender.com/api/v1/payments/1/pay \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"outcome":"success"}'

A Postman collection is included at docs/postman_collection.json and the specification at docs/openapi.yaml.
