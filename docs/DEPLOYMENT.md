# Deployment guide

The project is ready for **Render + PostgreSQL** (recommended free path) and also
works on Railway, Fly.io, Koyeb or any Docker host. The front-end and back-end
are served by the same Django deployment, so one HTTPS URL covers both.

> Deployment status: the configuration, build scripts and documentation in this
> repository are complete. The live URL and hosting-dashboard screenshots must be
> produced with the account that owns the deployment — see the checklist at the
> end.

---

## 1. What gets deployed

| Component | Technology | Hosting |
|---|---|---|
| Front-end | Django templates + `web/` CSS/JS, Chart.js | Served by the web service (WhiteNoise for static files) |
| Back-end | Django 6.1 + Gunicorn | Render web service / Docker |
| Database | PostgreSQL | Render Postgres, Neon or Supabase |
| Media | Local `/media` by default; optional Cloudinary/R2 URLs | Render disk or object storage |

The repository contains:

* `requirements.txt` — pinned production dependencies
* `build.sh` — install, `collectstatic`, `migrate`, optional demo seed
* `render.yaml` — one-click Render blueprint (web + Postgres)
* `Procfile` — Gunicorn start command for Heroku-style hosts
* `Dockerfile` + `docker-compose.yml` — container deployment
* `.env.example` — every supported environment variable
* `/healthz` — JSON health check used by Render

## 2. Option A — Render (recommended)

### 2.1 Push the repository to GitHub

```bash
git init
git add .
git commit -m "Rukomeza Market: full-stack marketplace"
git branch -M main
git remote add origin https://github.com/<your-username>/rukomeza-market.git
git push -u origin main
```

`.gitignore` already excludes `venv/`, `db.sqlite3`, `staticfiles/`, `media/`,
`backups/` and every `.env` file. **Do not commit secrets.**

### 2.2 Create the services

1. Sign in to <https://render.com>.
2. **New → Blueprint**, select the repository. Render reads `render.yaml` and
   creates:
   * `rukomeza-db` (PostgreSQL)
   * `rukomeza-market` (Python web service)
3. If the free blueprint cannot create a database in your region, create a
   **PostgreSQL** instance manually and paste its *Internal Database URL* into the
   web service's `DATABASE_URL` environment variable.
4. Confirm these environment variables on the web service:

| Variable | Value |
|---|---|
| `DATABASE_URL` | `postgresql://...` from Render/Neon (required) |
| `DJANGO_SECRET_KEY` | generated by Render, or a 50+ character random string |
| `DJANGO_DEBUG` | `False` |
| `DJANGO_ALLOWED_HOSTS` | `.onrender.com` (the exact hostname is added automatically from `RENDER_EXTERNAL_HOSTNAME`) |
| `MOCK_GATEWAY_SECRET` | generated, used to sign the mock webhook |
| `SEED_DEMO` | `true` for marking, `false` later |
| `PYTHON_VERSION` | `3.13.5` |
| `DJANGO_SECURE_SSL_REDIRECT` | `True` (default when `DEBUG=False`) |

5. Deploy. `bash build.sh` runs during the build:

   ```bash
   pip install -r requirements.txt
   python manage.py collectstatic --noinput
   python manage.py migrate --noinput
   python manage.py seed_demo        # idempotent: skips when data exists
   ```

6. Wait for the deploy log to finish and open
   `https://<service-name>.onrender.com/healthz`. It must return
   `{"status":"ok","database":true,...}`.

### 2.3 Create your own administrator (optional)

The seed creates `admin / Admin#2026` for demonstration. For a private admin,
open the Render **Shell** and run:

```bash
python manage.py createsuperuser
```

or change the demo password from the Django admin.

### 2.4 Custom domain and HTTPS

Render issues a free `*.onrender.com` TLS certificate. For a custom domain, add
it in **Settings → Custom Domains**, create the CNAME, then add the domain to
`DJANGO_ALLOWED_HOSTS` and (if using a proxy) to
`DJANGO_CSRF_TRUSTED_ORIGINS`, e.g. `https://market.example.com`.

## 3. Option B — Neon PostgreSQL + any app host

1. Create a project at <https://neon.tech> and copy the pooled connection string
   (`...?sslmode=require`).
2. Set `DATABASE_URL` to that value on your host.
3. Run the same `bash build.sh` build command and
   `gunicorn marketplace_project.wsgi:application` start command.
4. The settings parser understands `postgres://` and `postgresql://`, applies
   `sslmode=require` by default for non-local hosts, and keeps SQLite for local
   development.

Supabase and Aiven work the same way; use the session/pooled URL that allows
schema changes during `migrate`.

## 4. Option C — Docker / Fly.io / Railway

```bash
docker build -t rukomeza-market .
docker run --rm -p 8000:8000 \
  -e DJANGO_DEBUG=False \
  -e DJANGO_SECRET_KEY="$(openssl rand -hex 32)" \
  -e DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1 \
  -e MOCK_GATEWAY_SECRET="$(openssl rand -hex 32)" \
  -e DATABASE_URL="postgresql://user:pass@host:5432/rukomeza?sslmode=require" \
  rukomeza-market
```

For a complete local production-like stack with PostgreSQL:

```bash
docker compose up --build
# http://localhost:8000 — admin / Admin#2026
```

The container serves on port `8000`. On Fly.io set the internal port to 8000 and
use `fly postgres attach` to obtain `DATABASE_URL`.

## 5. Environment variables reference

| Name | Required | Default | Description |
|---|---|---|---|
| `DJANGO_SECRET_KEY` | production | insecure dev key | Signing key for sessions/CSRF. Never commit. |
| `DJANGO_DEBUG` | yes | `True` | Must be `False` in production. |
| `DJANGO_ALLOWED_HOSTS` | yes | `localhost,127.0.0.1,testserver` | Comma-separated hostnames. |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | custom domain | empty | Comma-separated `https://...` origins. |
| `DATABASE_URL` | production | empty (SQLite) | PostgreSQL connection string. |
| `DB_SSL_MODE` | no | `require` | `sslmode` for non-local PostgreSQL. |
| `DJANGO_SECURE_SSL_REDIRECT` | no | `True` when not DEBUG | Force HTTPS. |
| `MOCK_GATEWAY_SECRET` | production | dev value | HMAC secret for `/api/v1/payments/webhook/mock`. |
| `PAYMENT_GATEWAY` | no | `MOCK` | Active gateway identifier. |
| `SHIPPING_FEE` | no | `0` | Flat shipping fee. |
| `MAX_ORDER_LINE_QUANTITY` | no | `99` | Per-line checkout limit. |
| `SEED_DEMO` | no | `true` | Seed demo data during the build. |
| `DJANGO_TIME_ZONE` | no | `Africa/Kampala` | Display time zone. |
| `DJANGO_MEDIA_ROOT` | no | `./media` | Upload path (mount a disk for persistence). |

## 6. Post-deploy verification

Run these checks against the live URL:

```bash
curl -s https://YOUR-URL/healthz
curl -s -o /dev/null -w "%{http_code}\n" https://YOUR-URL/
curl -s https://YOUR-URL/api/v1/products | head -c 400
```

Then in a browser:

1. Register a customer, add a product to the cart, check out and complete the
   mock payment. The order timeline should show **Pending → Paid**.
2. Log in as `admin` and mark the order **Shipped** then **Delivered**.
3. As the customer, open the order and confirm the timeline and shipment.
4. Submit a review on the purchased product; try the same review from a
   different account and confirm it is refused.
5. Log in as `greenbasket` (seller), create a listing, change stock and confirm
   the public catalogue updates.
6. Open `/dashboard/reports/` and confirm the revenue and seller charts render.

Expected health response:

```json
{"status": "ok", "database": true, "time": "...", "version": "1.0.0", "debug": false}
```

## 8. Keeping the deployment alive for 14 days

* Render free web services sleep after inactivity but wake on the first request;
  the first visit can take ~30 seconds. Open the URL before marking.
* Keep the service and database resources in the same account; do not delete the
  blueprint after submission.
* If using Neon's free tier, it may suspend after long inactivity; the first
  connection resumes it. The `/healthz` endpoint is a cheap way to wake it.
* After marking, set `SEED_DEMO=false` so a re-deploy does not recreate demo
  users. The demo seed is idempotent and will not overwrite existing orders.
* Back up the database before any destructive change:
  `pg_dump "$DATABASE_URL" > backup.sql`.

## 9. Troubleshooting

| Symptom | Fix |
|---|---|
| `DisallowedHost` | Add the hostname to `DJANGO_ALLOWED_HOSTS`. |
| `CSRF verification failed` on a custom domain | Add `https://your-domain` to `DJANGO_CSRF_TRUSTED_ORIGINS`. |
| Static files 404 | Ensure `collectstatic` ran and WhiteNoise middleware is present (it is in settings). |
| `relation "store_user" does not exist` | `migrate` did not run; check the build log. |
| `database is locked` locally | SQLite only; production uses PostgreSQL. Checkout retries SQLite lock errors. |
| Images not persisting | Media is local by default; attach a Render disk to `/app/media` or use a CDN URL per image. |
| `seed_demo` reports data present | It is idempotent. Use `--reset` only on a disposable database. |
