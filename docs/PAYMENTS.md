# Payments — documented mock gateway

The marketplace ships with a **mock payment gateway**. It is deliberately simple,
fully testable and documented here, as allowed by the assignment brief
("a documented mock gateway" is an accepted alternative to Stripe/Paystack/
Flutterwave test mode).

No real card data is collected and no money moves.

---

## 1. Flow

```
Customer                Marketplace                         Payment record
   |                        |                                     |
   |-- POST /orders ------->| 1. validate cart + prices           |
   |                        | 2. atomic stock decrement           |
   |                        | 3. create Order (PENDING) --------->|
   |                        | 4. create Payment (PENDING) ------->| reference PAY-XXXXXXXX
   |<-- redirect to /payments/<order>/ --------------------------|
   |                        |                                     |
   |-- "Pay successfully" ->| 5. process_mock_payment(success)    |
   |                        | 6. Payment -> PAID, paid_at set --->|
   |                        | 7. Order PENDING -> PAID            |
   |                        | 8. OrderStatusEvent(PAID)           |
   |<-- order tracking -----|                                     |
```

A declined attempt records `Payment.status = FAILED`, increments `attempts` and
stores `failure_reason`, but leaves the order `PENDING` so the customer can try
again with another method. A successful retry moves it to `PAID` exactly once
(idempotent).

## 2. Endpoints

| Action | HTML | JSON API |
|---|---|---|
| Payment page | `GET /payments/<order_id>/` | `GET /api/v1/payments/<order_id>` |
| Pay (success/failure) | `POST /payments/<order_id>/` with `outcome=success\|failure` | `POST /api/v1/payments/<order_id>/pay` `{"outcome":"success"}` |
| Gateway callback | — | `POST /api/v1/payments/webhook/mock` |
| Order tracking | `GET /orders/<order_id>/` | `GET /api/v1/orders/<order_id>/tracking` |

### Example: direct API payment

```bash
curl -X POST https://YOUR-URL/api/v1/payments/12/pay \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"outcome":"success"}'
```

### Example: signed webhook

The webhook mirrors production gateways: the body is signed with a shared
secret using HMAC-SHA256.

```python
import hashlib, hmac, json, os, requests

secret = os.environ["MOCK_GATEWAY_SECRET"]
body = json.dumps({"reference": "PAY-1A9CBDF4223247F4", "outcome": "success"}).encode()
signature = hmac.new(secret.encode(), body, hashlib.sha256).hexdigest()

response = requests.post(
    "https://YOUR-URL/api/v1/payments/webhook/mock",
    data=body,
    headers={"Content-Type": "application/json", "X-Mock-Signature": signature},
    timeout=20,
)
print(response.status_code, response.json())
```

An invalid or missing signature returns `401 invalid_signature`. The webhook is
safe to retry: an already-paid payment returns its current state without creating
a second payment or a second `PAID` event.

## 3. Data recorded

| Field | Meaning |
|---|---|
| `gateway` | `MOCK` (or `STRIPE`, `PAYSTACK`, `FLUTTERWAVE` when implemented) |
| `transaction_ref` | Unique reference generated by the marketplace (`PAY-...`) |
| `provider_reference` | Gateway-side reference (`MOCK-PAY-...`) |
| `amount`, `currency` | Amount copied from the server-recalculated order |
| `status` | `PENDING`, `PAID`, `FAILED`, `CANCELLED`, `REFUNDED` |
| `attempts` | Number of mock attempts |
| `failure_reason` | Human-readable decline reason |
| `raw_response` | JSON payload that would come from the gateway |
| `paid_at` | Timestamp of the successful charge |

Cancelling a paid order changes the payment to `REFUNDED` and records the reason;
cancelling a pending order sets the payment to `CANCELLED`. Stock is returned to
inventory in the same transaction.

## 4. Swapping in a real gateway

The service boundary is intentionally small. To enable Stripe/Paystack/
Flutterwave test mode:

1. Add the provider SDK to `requirements.txt`.
2. Add `STRIPE_SECRET_KEY` / `PAYSTACK_SECRET_KEY` / `FLUTTERWAVE_SECRET_KEY` as
   hosting environment variables. **Never commit them.**
3. In `store/services/payments.py`, implement a `process_{gateway}_payment`
   function that:
   * creates the provider charge for `payment.amount` in test mode;
   * verifies the provider webhook signature;
   * updates the same `Payment` row and calls `Order.transition_to('PAID')`.
4. Allow the gateway in `order_create` (`gateway` field) and render its checkout
   element in `payment.html`.
5. Keep the mock gateway available as a fallback for the oral defence.

The order lifecycle, stock handling and price snapshots do not change.
